POLICY SEARCH CONTRACT

PolicySearch.search(game, power)                             ==> SearchResult
BestResponseSearch and DiLPiKLSearch implement PolicySearch.
adaptive.asSearch(initialLimit, generator, priorFactory) supplies the same
interface. Each call generates fresh pools; the prior factory binds each
movement root. Other phases skip discovery and prior binding.
adaptive.search(...) retains its reports.
ResponseDiscovery discovers additions; it does not select a complete policy.

SearchResult.distribution is the policy to sample. meanValues are aligned raw
payoff means: fixed anchor opponents for BestResponseSearch, sampled history
for DiL-piKL.
They exclude search penalties and are not fresh returned-policy evaluations.
samplesPerCandidate counts observations per mean, including cached payoffs,
but excluding extra evaluator rollouts and earlier adaptive solves.
Root pools must contain distinct complete actions and positive prior support.
BestResponseSearch may select an individual zero-prior action; DiL-piKL assigns it no mass.
BestResponseSearch and ResponseDiscovery share fixed-sample payoff measurement;
each retains its own sampling order and candidate-selection rules.


FIXED-POOL BASELINE

PaperSearchProfile implements SearchProfile.
PaperSearchProfile.forState(snapshot)
    -> Spring 1901 movement: uniform {10^-2, 10^-1.5, 10^-1, 10^-0.5}; play 10^-2
    -> later turns: uniform {10^-4, 10^-3, 10^-2, 10^-1}; play 10^-4
    -> ADAPTIVE temperature; caller supplies iterations and seed

profile.solver(evaluator, generator, limit, iterations, seed) ==> DiLPiKLSearch
profile.solver(..., seed, PolicyOutput.AVERAGE)               ==> averaged output
solver.search(game, power)                                  ==> SearchResult
solver.solve(game, pools, trials)                           ==> JointSearchResult
solver.trace(game, pools, checkpoints, trials)               ==> List<JointSearchResult>

search() generates pools; solve() accepts explicit pools. Both validate them.
    -> freeze complete, distinct actions and anchor probabilities
    -> initialize Q = 0 and per-type utility statistics
    -> each iteration:
         -> form policies from previous Q and temperature
         -> accumulate each type's probabilities, including the playing type
         -> independently sample a lambda and action per nation
         -> freeze opponents; evaluate each nation's alternatives
         -> update equal-weight mean payoffs Q and per-type utility statistics
    -> return selected playing policies, population mixtures, Q, and temperatures

policy(a) proportional to exp((Q(a) + lambda * logPrior(a)) / (kappa + lambda))
kappa_t = 3 S_t / (10 sqrt(t)); S_t measures per-type policy-averaged utilities.
Startup is uniform over positive-prior actions. Zero-prior actions stay excluded.
Older solver constructors without a schedule retain ZERO temperature.
Older factories and constructors retain FINAL output.
FINAL uses the policy after the last update. AVERAGE uses the equal-weight
average of pre-update policies from iterations 1 through T, including startup.
The output choice does not change sampling, Q, temperatures, or evaluation work.
JointSearchResult retains immutable Settings: population, playing lambda,
and temperature schedule. Construction validates the selected policies.
solved.withOutput(choice) selects either output from the same solve.
Selecting the existing output returns the same result.
The profile-taking overload checks the recorded settings exactly.
Manually constructed results must also supply settings and temperatures.
trace() takes increasing checkpoints ending at the iteration budget.
It records one continuous solve; no restart, extra sampling, or extra trials.
Each immutable snapshot reports its own completed iteration count.

TYPE RECEIPTS

TypeReceipt.exact(solved, trials)                            ==> List<TypeReceipt>

Same root and payoff function as the solve:
    -> read the recorded solve settings
    -> freeze population mixtures in the selected output mode
    -> compute fresh values against those opponents
    -> read every type, including a separate playing lambda if needed
    -> compare with fresh regularized responses at kappa=0 and final kappa

exact() enumerates all retained joint actions and requires deterministic payoffs.
sampled() uses its own RNG; at least two samples; action-value standard errors.
Numeric header: lambda, population weight, playing flag (0/1), temperature,

temperature residual. Then probability, fresh value, standard error per action.
Nation and output mode are separate metadata; the numeric layout is unchanged.
Temperature always means final recorded kappa, even for an averaged policy.
All checks concern retained actions; none certifies full-game equilibrium.
