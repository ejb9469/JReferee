AGENTS PACKAGE: CODE FLOW

The package chooses complete orders for one nation in non-press Diplomacy.
An action is those orders. A policy gives probabilities to candidate actions.
The anchor is a reference policy. A type is one lambda value: larger lambda
puts more weight on following the anchor.

1. Prepare
----------
Use an isolated Game at the position to search, without a saved checkpoint.
Movement, retreat, and adjustment processors belong to Game.
SzykmanJustice is the default movement processor. JUDGE is an explicit faster
option that can disagree on difficult positions.

2. Choose settings and candidates
--------------------------------
PaperSearchProfile implements SearchProfile and selects the paper's test-time
lambda settings from the game moment. Spring 1901 movement uses OPENING;
later turns use STANDARD. Both select the adaptive temperature schedule.
SearchProfile.solver(...) builds the existing DiLPiKLSearch.
Pass PolicyOutput.AVERAGE as its last argument for averaged output.
The older factory and constructors retain PolicyOutput.FINAL.

LegalOrderGenerator supplies individual options. ActionGenerator builds
complete candidates. Validation checks phase, units, targets, and quotas.
Movement orders cover every unit; retreats may be omitted; required disbands
must be named. Every living nation supplies an action, even if it is empty.

Freeze each pool and its anchor log-probabilities for the solve. Generation
scores and search probabilities do not replace the anchor probabilities.
Use explicit pools for small checks or UniformActionGenerator as a temporary
baseline. Older convenience constructors still use PlausibleActionGenerator.
Both default movement generators exclude convoys.

ProvinceScope can restrict a tactical fixture. ScopedActionGenerator filters
options before generation and restores full-state anchor values afterward.
It preserves the board and scoring. Explicit pools need their own scope check.
Geographic restrictions are not part of the paper profile.

3. Search and evaluate
---------------------
DiLPiKLSearch.solve(game, pools, trials)
    -> start Q and type-utility statistics at zero
    -> repeatedly sample each nation's lambda and complete action
    -> accumulate every type's pre-update action probabilities
    -> evaluate alternatives against the same sampled opponents
    -> update mean raw payoffs Q and adaptive temperatures
    -> return selected playing policies and population mixtures

trace(game, pools, checkpoints, trials) records selected completed iterations
within that same solve. Checkpoints increase and end at the configured budget.
It copies values and policies without restarting or drawing extra samples.

JointActionEvaluator -> optional cache -> Simulator.peek() -> Evaluator.
peek() resolves one phase and restores the root before evaluating the successor.
Caching requires deterministic processors and evaluation.
RolloutEvaluator uses a separate game to reach winter before leaf scoring.

The policy formula is in Algorithm 1 / Equation 5 of arXiv:2210.05492.
Section 2.2 supplies kappa_t = 3 S_t / (10 sqrt(t)). Each type observes its
policy-weighted utility; Q uses equal-weight counterfactual payoff averages.
Startup and per-type observations follow the public implementation. There is
no variance floor or prior smoothing.

FINAL uses the policy formed after T updates. AVERAGE uses the equal-weight
average of the T policies used before those updates, including startup.
Each nation and lambda has its own average; output-only types are also tracked.
Q, temperatures, sampled actions, and evaluation work are identical in both modes.
JointSearchResult.withOutput(choice, profile) switches output without another solve.

4. Read the receipts
-------------------
TypeReceipt.exact(profile, solved, trials) enumerates retained joint actions.
Use deterministic payoffs. TypeReceipt.sampled(..., samples, seed) instead
estimates fresh values using common opponent draws and a separate random seed.
It reports per-action standard errors; these are not error bounds for the
derived response differences or regularized gains.

Each receipt covers one nation and lambda, including an output-only playing
lambda when necessary. Opponents use population mixtures in the same output mode.
Q describes opponent history; fresh values describe these selected opponents.

Response difference: largest probability difference from the fresh best
response under the anchor penalty. Regularized improvement: the payoff
improvement after that penalty. Both use Equation 4, with kappa=0.
A second probability difference includes the final recorded kappa. An averaged
policy is not generally a softmax at that kappa.

values() retains the numeric order documented in contract_ideal.txt.
Nation and FINAL/AVERAGE output remain separate receipt metadata.
toString() prints the same results as a receipt. Diagnostics leave the search
result and game unchanged, but may populate the shared evaluation cache.

5. Play and compare
------------------
Sample the requested nation's playing policy and submit its orders.
The caller handles the actual match, game-ending rules, and next position.

PaperSearchConsoleApp [seed] [iterations] runs the complete two-plan fixture
with the paper profile. Defaults: seeds 7, 17, 31; 131072 iterations per seed.
It prints Q, probabilities, temperatures, and fresh checks for both output modes
at every checkpoint, then both playing-type receipts at the final checkpoint.
Smaller explicit budgets remain valid.

TwoActionReference independently runs Algorithm 1 on the measured two-by-two
payoff matrix, using its own sampling, policy formula, payoff sums, and Welford
variance updates. It uses no production solver or temperature/policy helpers.
Both calculations use equal-weight observations and the same startup convention.
Agreement within 1e-8 is an implementation check, not a convergence threshold.
The fixture's known 50/50 answer and remaining improvement are reported separately.
The reference also accumulates probabilities independently for AVERAGE.

Section 3.2 studies averaged and final policies in two-player zero-sum games.
That guarantee does not extend to seven-player Diplomacy. Averaging may still
perform better there; full-game comparisons must establish playing strength.

The uniform anchor, fixed scope, and winter evaluator are temporary test choices.
Retreat orders are omitted. No candidate discovery or tactical rules are added.
The older CounterSearch applications retain their expansion experiments.

AdaptiveDiLPiKLSearch remains an optional wrapper: discover responses, append
actions, and restart a fixed-pool solve. NO_RESPONSE_FOUND describes discovery,
not convergence. The paper omits double-oracle exploration during training.

Completing an iteration budget does not prove equilibrium. Next come full-game
execution, a human-imitation anchor, learned proposals and values, and self-play
training with the anchor held fixed.
