VALUE EXPORT ADMISSION

ValueExportApp dispatches by source_type, then calls the provider-neutral
ValueSourceAdapter.Result.validatePositions before writing any game targets.
The manifest records position_validation=jreferee-value-standing-units-v1.
This is a limited sanity check, not historical adjudication replay.

Any retained position with more than 34 standing units rejects the whole game
as TOO_MANY_STANDING_UNITS. Diagnostics identify every offending retained
position's zero-based index, year, phase and count. Existing source diagnostics
and available literal scoring/limit labels remain in the game index.
Earlier positions are not kept with targets potentially affected by invalid
later play. Nothing is repaired, silently skipped or blacklisted by game ID.
The reward contract and existing provider-specific ending checks are unchanged.
TEST identities are indexed as before; TEST payloads remain unopened.
