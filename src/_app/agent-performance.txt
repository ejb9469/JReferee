OPTIONAL AGENT PERFORMANCE DIAGNOSTICS

Work in a separate project/output copy while PolicyMatchApp is running.
Do not rebuild its active classes, overwrite its models or run substantial
profiling workloads alongside the match. There are no workers or threads.

FIRST CHECKS

Main classes, without arguments:
  performance.PerformanceStatsSelfCheck
  performance.PerformanceReportSelfCheck
  testing.selfcheck.AgentPerformanceSelfCheck

The last check uses small synthetic/model-free fixtures and temporary files.
It covers movement, retreat and adjustment decisions, all three agent methods,
root restoration, recorder readback, warm-up separation and report rejection.

To include the actual neural value and coherent typed movement path:
  testing.selfcheck.AgentPerformanceSelfCheck
  data/value-self-play-java-v1/model.bin
  data/movement-linear-v1/policy.bin
  data/movement-self-play-java-v3/model.bin

One value-model argument without movement paths is also supported.

For the movement-stage extension, the focused check is:
  phase.movement.AdjudicationPolicySelfCheck
  --timings

It checks all three adjudication policies with absent, enabled and disabled
timings; successful and rejected attempts; unchanged results and counters;
and the three stages remaining inside the inclusive movement duration.
This mode does not load DATC fixtures or run the search/permutation suite.
The same class without arguments retains its full existing adjudication check.

FIXED-DECISION PROFILING

Main class:
  _app.AgentPerformanceApp

Nine positional arguments, from the repository root:
  <completed-individual-archive-directory>
  <zero-based-phase-index>
  <power-name>
  <value-model.bin|baseline>
  <anchor.bin|none>
  <gru-model.bin|none>
  <additional-warmups>
  <measured-repeats>
  <new-output-directory>

For example, after the value match is finished, a candidate-leg opening:
  data/value-match-v1-vs-supervised/archives/pair-00000-candidate
  0 ENGLAND
  data/value-self-play-java-v1/model.bin
  data/movement-linear-v1/policy.bin
  data/movement-self-play-java-v3/model.bin
  1 3 data/agent-performance-v1

Use the individual game's archive, not the match's top-level directory.
The directory must have its completion manifest and pass full replay.
The current reader accepts JUDGE archives only.
The reference leg instead requires data/value-java-v1/model.bin.
In a candidate leg, only its focal power uses the candidate value model.
An earlier completed experiment can be used with its own exact artifacts.

For an archive without neural values, use baseline. For no movement models,
use none none. An anchor-only seat uses its anchor path followed by none.
Every supplied model identity must exactly match the selected recorded seat.
Budgets, output policy, generator choices, adjudication settings, cutoff and
all three decision seeds come from the archive, not new command-line budgets.
The output parent must exist; the output directory must be new and outside
the input archive. Input archives and models are opened read-only.

The app loads/replays once and loads models once. It then executes one
unprofiled reference decision, the requested additional warm-ups, and the
requested measured repetitions. Every execution gets a fresh simulation game
at the same position, using the same seeds and normal AgentSettings path.
Models are shared immutably. No joint-action cache is activated.

Each warm-up/measured decision must exactly match the current unprofiled
reference: candidate ordering, priors, probabilities, search means, selected
action and seeds. Only elapsed time is excluded. Simulation roots must remain
unchanged. A mismatch fails without publishing a completion report.

The report separately states whether current execution reproduced the
historical archived decision. A mismatch there prints a warning: source/JVM
changes can change work even when profiling on/off agrees in the current
build. Do not call such a timing difference a same-work speedup.

This is one focal decision, not a game against seven independently executed
agents. Its opponent pools are generated by the focal agent, just as in the
normal runner. It does not rerun or alter the original experiment.

REPORTS

performance.json: completion receipt, context, exact model identities, budgets,
  rules, seeds, environment, decision SHA-256, section measurements and counters.
  Published last, with sizes/SHA-256 receipts for both CSV files.
timings.csv: section, operation, calls, total_nanos, mean_millis, min_nanos,
  max_nanos. Strings are quoted and decimal formatting is locale-independent.
work.csv: section, counter, value.

Sections are preparation, warmup and measured. Never add warm-up or preparation
to measured decisions. The mandatory unprofiled reference also warms the JVM.
It is a correctness check, not an overhead baseline: its outer scope includes
fresh-game creation and root checks, outside the agent decision timing.
These are elapsed wall times, not CPU times or a controlled cold-disk test.
OS cache, GC, JIT, background load and timer overhead affect results.
No percentiles, allocation estimates, automatic GC or strength claims.

Timings are inclusive: agent decision includes generation/search/sampling;
search includes generation and solving; joint evaluation includes root
simulation and continuation evaluation. Movement and neural inference overlap
those enclosing scopes. Do not sum rows or interpret them as exclusive costs.
Rollout generation times generator calls, not preceding legal-catalog creation.
Continuation evaluation includes the remaining continuation overhead.
Missing timing rows mean that operation was not entered, not that it was free.

MOVEMENT STAGES

The existing movement total now contains three sequential stages:
  movement preparation:
    Input validation, normalization, movement-order conversion, and adjudicator
    construction, including JUDGE's canonical sorting.
  movement adjudication:
    The existing producer.judge() call, including all of that policy's internal
    components, passes, trials, probes and fallbacks.
  movement result conversion:
    MovementResult.from, including outcome/dislodgement/convoy-arrival facts.

These are not additional work to add to movement. The total also includes
scope-management and between-stage overhead, so the three totals need not
sum exactly to it. Stage calls count attempts, including exceptional exits.
If preparation fails, adjudication and result conversion are not entered.
Existing movement/adjudicator work-counter meanings remain unchanged.

With absent Diagnostics, scopes use one shared no-op: no clock reads, timing
objects or timing-map updates. A supplied Diagnostics with disabled timings
still records its work counters, as before. Enabled successful movements add
six clock reads and three short-lived timer objects compared with the former
outer-only timer. No per-order/recursive timers, logging or synchronization.
The existing agent profiler and reports include the new rows automatically.

Work counters reuse JointActionEvaluator and MovementProcessor diagnostics.
Movement counts include both speculative root and continuation work; in a
profiled whole game they also include actual resolution. Attempts and failed
attempts are counted. Internal Judge passes do not get separate counters.
The profiler prints measured counters and timings; detailed warm-up data is
available in the files. Report writing itself is outside the timing sections.

For before/after comparisons use the same archive, phase, power, models,
budgets, seeds, JVM/heap settings and repetition counts. Compare decision
SHA-256 and work counters as well as elapsed time. One position is not a
representative whole-game speed estimate. Sample several completed positions
separately before choosing an optimization; do not aggregate nested rows.
Evaluation archives remain excluded from training.

OPTIONAL WHOLE-GAME INTEGRATION

Existing APIs remain disabled by default; no settings/record schema changes.
The jreferee.perf development property does not enable these new integrations.
Do not add diagnostics to AgentSettings, GameRunner.Options or model identities.

Create one new performance.AgentPerformance(true) for a sequential run.
GameRunner.run accepts it as the final argument after both observers.
SelfPlayRecorder.run accepts it after the decision observer.
Use performance.printTo(System.out), or PerformanceReport.write with a context
map and List.of(performance.snapshot("game")) after the run has returned.
Do not reuse one collector across unrelated runs or concurrent calls.

Whole-game hooks additionally time actual phase resolution and both observer
callbacks. Recorder hooks cover opening/writing the header, phase validation/
serialization/flush, and final file checksums/readback/manifest publication.
Archive finishing is integrity validation, not a full adjudication replay.
The standalone app separately times SelfPlayDataset.open for full read/replay.
Archive fingerprints can differ because their existing elapsed_nanos fields
are diagnostic; settings, decisions, rules, seeds and outcomes are unchanged.

This slice changes no generation/filtering, search algorithm, continuation
horizon, adjudication policy, cache policy, training, model promotion or match
protocol. Existing proposal/search-budget benchmarks remain unchanged.
