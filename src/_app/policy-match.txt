Pairing and termination
-----------------------
One rotation visits each power in Nation order. Each power gets a fresh
pair seed, shared between its REFERENCE and CANDIDATE games. Only the focal
seat's final score is compared. The other six seats always remain reference.
Each complete rotation costs fourteen games; the fixed range is 1..32.
The first side alternates between successive pairs to balance execution order.
Both games start from standard Spring 1901 with matching phase/power seed
streams. Positions and random draws can diverge after different actions.
Shared seeds do not force identical trajectories.

The 1930 boundary remains an artificial cutoff, not an agreed draw.
GameRunner ends at a solo or after the final year's complete Fall,
including retreats and ownership updates, before winter adjustments.
This launcher adds no draw voting, repetition draws or early stopping.
Changing the horizon changes both the evaluation metric and exact-cutoff
leaf handling. Keep it identical between sides and across compared runs.
Retreat/adjustment proposals and UNIFORM continuation remain unchanged.
The fixed search budget is a pilot setting, not paper-strength search.

Scores and uncertainty
----------------------
The primary metric is mean(candidate focal SoS - reference focal SoS).
SoS uses the existing 0..1 scale, with a solo worth 1/0.
Positive favors the candidate against this particular reference population.
It is not Elo, a win rate or a universal ranking.

All planned games contribute, INCLUDING explicit year-limit cutoff scores.
The report separately counts solos, cutoffs and focal solo wins per side.
A cutoff score is not an eventual outcome or a draw label. Do not filter
to only naturally ended games, which would change the sample.

Each complete seven-power rotation contributes one mean paired delta.
The overall standard error uses those rotation means, not phases, seats
or nominally independent legs. Per-power errors use one pair per rotation.
One rotation reports null, not zero, standard error. Two rotations are only
an operational pilot with very weak uncertainty evidence.
There is no automatic extension, confidence threshold or promotion.

Artifacts and compatibility
---------------------------
  plan.json
  games.jsonl
  archives/pair-00000-reference/
  archives/pair-00000-candidate/
  ...
  manifest.json

The plan precedes play and records exact seat artifacts, rules, initial
position and schedule. The journal is flushed after each replay-verified
game and binds its side, seed, UUID, logical key, archive hash and score.
The final manifest is published atomically only after all planned games,
a second replay/receipt pass and summary recomputation succeed.
Missing manifest means incomplete. Preserve partial outputs for diagnosis.

The match-family schema remains jreferee-policy-match-v1. New value runs
add comparison=VALUE to BOTH the plan and manifest. Absence means the old
proposal-only contract; unknown or null comparison markers are rejected.
Value-run role UUIDs use a separate domain. Removing a marker cannot
reinterpret a value run as an old policy run, including an A/A comparison.
Existing policy plans, game IDs and manifests are unchanged and readable.
Older launcher code cannot verify the new value-mode receipts.

The existing ArchiveReplayApp accepts both modes through the updated
PolicyMatchApp verifier. Its reference/candidate settings and per-seat
model identities display the same recorded evidence. No UI change is needed.

To replay/recompute any completed policy or value comparison without models:

  _app.PolicyMatchApp --verify <completed-match-directory>

Flushing is not an fsync guarantee; hashes are not signatures. Readback
holds one game's history at a time. Existing limits remain 64 MiB per
archive file and 4 MiB each for plan, journal and match manifest.

Individual archives retain ordinary self-play outcome eligibility metadata.
That does NOT authorize training on evaluation games, including reference
legs or naturally ended solos. Never pass these cohorts to a cache builder
or trainer. No historical TEST data is opened and no model is updated.

Objective and selection
-----------------------
The architecture is the existing seven-power ValueNetwork. Its hidden size
comes from the initial checkpoint, not a separately chosen command argument.
Movement and winter-adjustment positions retain the original board/year/phase
encoding. Retreats and terminal boards are not training inputs.
The observed solo target is winner=1 and every other power=0.
There are no cutoff pseudo-labels, TD bootstraps or discounted targets.

All TRAIN positions are shuffled once per epoch using the configured seed.
The objective remains position-weighted MSE over seven powers. Longer games
contribute more weight. Validation reports also include equal-game MSE/MAE,
per-power errors and phase/communication subgroups. TRAIN-mean and current-SoS
baselines use the existing supervised helpers.

The initial checkpoint is epoch 0 and is eligible for selection.
Only a strictly smaller validation-position MSE replaces it; ties retain the
earlier checkpoint. The optimizer is fresh, never resumed. Later self-play
value warm starts must use the same whole-game split seed.
The selected checkpoint is reloaded and its validation MSE reproduced.
Epoch 0 may therefore be the correct final result, not a failed run.

These positions are correlated within games, and only completed solos supply
targets. Lower MSE on 16 held-out completed games is not a strength claim.
No model promotion or evaluation extension is performed.

Windows PowerShell: run from the repository root
------------------------------------------------
The following block performs the focused self-checks, verification, fitting
and export. It stops at the first failure and never resumes partial outputs.
Keep partial directories for diagnosis; use new names for a deliberate rerun.

$ErrorActionPreference = 'Stop'
$Python = (Resolve-Path '.venv\Scripts\python.exe').Path
$Initial = 'data/value-network-v1/best.pt'
$Output = 'data/value-self-play-v1'
$Export = 'data/value-self-play-java-v1'
$Cohort = '641efbc7b8dcf796ddb8880b6f838e2b3c2ba867ae82989d4f24c4d8d09d6cf1'

foreach ($directory in @($Output, $Export)) {
    if (Test-Path -LiteralPath $directory) {
        throw "Output already exists: $directory"
    }
}
if ((Get-FileHash -LiteralPath $Initial -Algorithm SHA256).Hash.ToLowerInvariant() -ne
        'b70b22cf32b6d29e6d17cc06cf1df612ec038f9a1deaf9dca825a5d99ec1caf6') {
    throw 'Initial supervised value checkpoint differs.'
}
$Caches = @(
    for ($batch = 0; $batch -lt 32; $batch++) {
        $root = if ($batch -lt 29) {
            'data/self-play-round3-main'
        } else {
            'data/self-play-round3-recovery'
        }
        Join-Path $root ('batch-{0:D2}/cache' -f $batch)
    }
)
foreach ($cache in $Caches) {
    if (-not (Test-Path -LiteralPath (Join-Path $cache 'manifest.json') -PathType Leaf)) {
        throw "Missing completed cache: $cache"
    }
}
$Specification = Join-Path ($Caches[0]) 'value/specification.json'
function Invoke-ValuePython {
    param([string[]]$Arguments)
    & $Python @Arguments
    if ($LASTEXITCODE -ne 0) {
        throw "Python failed with exit code $LASTEXITCODE. Stop before continuing."
    }
}
Invoke-ValuePython @('-B', '-m', 'neural.test_value', '--spec', $Specification)
Invoke-ValuePython @('-B', '-m', 'neural.test_self_play_value', '--spec', $Specification)
$Training = @(
    '-B', '-m', 'neural.self_play_value_train',
    '--initial-value', $Initial, '--expected-cohort', $Cohort,
    '--epochs', '10', '--batch-size', '128', '--learning-rate', '0.0001',
    '--seed', '7', '--threads', '4', '--verbose', '--cache'
) + $Caches
Invoke-ValuePython ($Training + @('--verify-only'))
Invoke-ValuePython ($Training + @('--output', $Output))
Invoke-ValuePython (@(
    '-B', '-m', 'neural.self_play_value_export',
    '--checkpoint', "$Output/best.pt", '--training', "$Output/training.json",
    '--output', $Export, '--examples', '32', '--threads', '4', '--cache'
) + $Caches)
Write-Host 'Python stages finished. Build the Java project and run the checks below.'

The checkpoint schema is jreferee-self-play-value-network-v1.
The report schema is jreferee-self-play-value-training-v1.
The Java export schema is jreferee-self-play-value-java-v1, magic JREFSVL1.
The value cohort hashes the ASCII prefix
  jreferee-self-play-value-cohort-v1\n
then decimal split seed plus newline, then sorted raw dataset/manifest hashes.
It intentionally differs from the policy cohort hash over the same caches.

The new big-endian model header contains four UTF-8 strings (export/model/
reward/exact specification), five raw SHA-256 identities (spec/checkpoint/
cohort/training report/initial checkpoint), int64 split seed, int32 dataset
count, sorted pairs of raw dataset/manifest hashes, int32 epoch and hidden size.
The parameter count, named float32 tensors and trailing checksum then use the
existing value format. Java recomputes the cohort identity while loading.
Old JREFVAL1 exports still require epoch >= 1; only JREFSVL1 permits epoch 0.
NeuralValueModel.selfPlay() exposes the new immutable provenance.
cacheManifestSha256() is only for supervised models and rejects self-play
models rather than pretending a training receipt is an old cache manifest.

parity.bin retains JREFVCK1 and contains no targets or game identities.
It contains ten synthetic boards plus up to 32 evenly spaced positions from
the combined VALIDATION split. export.json records their source references.
java_parity_verified=false is export-time metadata; do not edit it afterward.
